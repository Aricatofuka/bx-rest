# bx-rest — демо для Node.js

Пример использования [`bx-rest`](../bx-rest) на сервере. В отличие от
браузерных демо, здесь нет интерфейса: [index.mjs](index.mjs) по очереди
показывает пять сценариев и печатает, что произошло.

1. **Два портала одновременно.** Два клиента `new BXRestNavvy(settings)` со
   своими адресами работают параллельно, глобальные `BXRestSettings` не
   нужны. См. раздел README библиотеки «Несколько порталов».
2. **`retryOnQueryLimit: true`.** 12 запросов сразу. Если портал отвечает
   `QUERY_LIMIT_EXCEEDED`, библиотека повторяет запрос через 1 и 2 секунды.
   Свой `middleware` печатает каждую попытку.
3. **`throttle: true`.** 6 запросов уходят не чаще 2 в секунду.
4. **`timeout: 1`.** Запрос дольше 1 мс отменяется с `BXRestTimeoutError`.
5. **Ошибка Bitrix.** Вызов несуществующего метода приходит как
   `BXRestApiError` со статусом и кодом ошибки.

Сценарии 2–4 описаны в разделе README библиотеки «Повтор, таймаут и очередь
запросов».

Код — обычный JavaScript (ESM) без сборки, с `// @ts-check`: редактор
подсказывает и проверяет типы bx-rest. Проверить типы из командной строки:
`npm run check`.

## Запуск

Из корня репозитория (нужно один раз собрать библиотеку и поставить
зависимости всех демо):

```shell
npm run demo:bootstrap
```

Либо вручную:

```shell
# из корня репозитория
npm run build

# здесь
npm install
```

### Без портала

```shell
npm run mock
```

Демо поднимает две заглушки портала на `127.0.0.1` ([mock-portal.mjs](mock-portal.mjs)).
Они отвечают с задержкой 20–60 мс и, как настоящий портал, ограничивают
частоту запросов: до 10 подряд, дальше 2 в секунду, сверх этого — 503
`QUERY_LIMIT_EXCEEDED`. Поэтому во втором сценарии видно, как библиотека
повторяет запросы.

### С настоящим порталом

Нужен входящий вебхук (Разработчикам → Другое → Входящий вебхук) с правами
`user` и `crm`. Демо только читает: `server.time`, `user.current`,
`crm.deal.list`, — и ничего не создаёт и не меняет.

```shell
# bash
BX_WEBHOOK_A=https://<портал>.bitrix24.ru/rest/1/<секрет>/ npm start

# PowerShell
$env:BX_WEBHOOK_A = 'https://<портал>.bitrix24.ru/rest/1/<секрет>/'; npm start
```

`BX_WEBHOOK_B` — необязательный второй портал (или второй вебхук того же
портала) для первого сценария. На настоящем портале запас лимита больше, чем у
заглушки, поэтому во втором сценарии повторов обычно не будет.

Адрес вебхука в лог не попадает: свой `middleware` печатает только имя
метода, статус и время. Учтите, что ошибка axios содержит адрес запроса
целиком, — поэтому демо выводит из ошибок только нужные поля.

Язык вывода — русский или английский, по языку системы (`LANG` или локаль
Node.js).
